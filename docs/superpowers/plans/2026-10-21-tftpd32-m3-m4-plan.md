## 2. 阶段方案

### 阶段 A：真机基线回归（阻塞项最小、收益最大）

目标：在 E2（手机 + PC/2in1）上补齐 M1/M2 的**报文级对拍**与**后台存活**，把“模拟器环形回环”结论升级为“与原版一致”。

| 任务 | 内容 | 产出/验收 | 状态 |
|---|---|---|---|
| A1 | 真机安装：`assembleHap` → `hap-sign-tool` 签名 → `hdc install`，确认服务可启动、四服务端口监听 | 安装脚本可用，端口 6900/5140/1230/5300 可达 | 已完成（模拟器验证流水线；`hvigorw` 需 `DEVECO_SDK_HOME` + jbr 的 java 在 PATH） |
| A2 | 组网：手机与 PC 同一网段（热点/同路由），关闭 PC 防火墙对应 UDP 端口 | 双向 `m2tool`/`otftp2` 可达 | 未执行（无真机） |
| A3 | 与原版 v4.74 对拍：TF-01/02/04、OP-*、RE-01/03/05、TC-01/02、SL-01、ST-01、DN-01~03、MD-02 | 逐条记录于测试方案 §6，差异为零或列入 §5 平台偏差 | 阻塞（需真机 + 同网段 PC） |
| A4 | 后台存活：退后台 8h，每 30min 由 PC 发 syslog/NTP/TFTP 探测 | NF-05 通过，无 socket 断开 | 阻塞（需真机） |
| A5 | 吞吐：10MB GET/PUT ×5，记录 MB/s 与原版同机对比 | NF-06 通过 | 阻塞（需真机） |
| A6 | LP64 审计：`sizeof(long)`、`%ld`、`%I64d`、`unsigned long` 定宽、`LARGE_INTEGER` 布局 | 审计清单 + 修复 | 已完成，见测试方案 §6.14.1（8 项，6 项已修，1 项转 M3） |

风险：无真机则 A3~A5 阻塞；此时先做 B，A 保留为发布前门禁。

## 3. 测试方案补充

1. **DHCP 测试必须二层广播**：模拟器不可用；真机 + 同网段 PC。
   - 工具：扩展 `tools/m2tool.c` 增加 `dhcp discover|request|release`（可指定 MAC/主机名），PC 侧用 `netsh`/scapy 对拍。
   - 用例：DH-01 DORA、DH-02 租约持久化、DH-03 BootFile+siaddr、DH-04 池耗尽、DH-05 自定义选项 42。
2. **组播测试**：`otftp2` 增加 `mcast=<group>:<port>`；两个客户端同组，验证 RFC2090 的 ACK/超时行为。
3. **回归门禁**：新增 C 单元测试目标（`entry/src/main/cpp/test/`，CMake 可选 target），覆盖 OACK 解析、DHCP 选项编码、租约分配/回收；每次提交本地跑，M3 起纳入。
4. **自动化冒烟**：`uitest` 脚本化（`dumpLayout` 校验页签、开关、配置回填），替代手工点击；`m2tool` 作为服务探针。
5. **对拍矩阵**（沿用 §7 通过标准）：P0 全过；P1 ≥95%；差异必须归入 §5 平台偏差或缺陷表。

## 4. 风险与决策点

| 风险 | 影响 | 对策 |
|---|---|---|
| 无真机 / 无二层网络 | A、B7、C1 阻塞 | 先做 B1~B6 的代码与单元测试，真机到位后集中对拍 |
| 鸿蒙组播权限/加入组限制 | C1 可能降级 | 真机先做最小的 `IP_ADD_MEMBERSHIP` 验证，失败则组播列为平台偏差 |
| `bootpd.c` 依赖 Win32 网络接口 API | B1 工作量 | 先在 `ip_pal.c` 做网卡枚举/广播的 PAL 验证，再移植主体 |
| 27 个 DHCP 键使 ini 变大 | 可忽略 | 与原版键名一致优先 |
| GPLv2 合规遗漏 | 交付风险 | D4 前做一次许可证头审计 |

## 5. 建议顺序

1. **A1/A2 + A6**（真机通路与 LP64 审计）——无真机则跳过 A3~A5。
2. **B1→B2→B3**（DHCP 主体与配置），**B4/B6** 随后，**B7** 与 A3 合并执行。
3. **C1/C2**，**C5** 视优先级。
4. **D1~D5** 在全部 P0 用例通过后启动。
