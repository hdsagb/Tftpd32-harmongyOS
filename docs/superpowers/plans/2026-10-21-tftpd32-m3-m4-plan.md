### 1.2 未接线配置键台账（A2/A3 清账：7 个，全部为 N/A 或已由其它机制承担）

逐项对照 `reference/tftpd64` 的 `_common/settings.h`、`_services/settings.c` 与各消费点核实：

| 键 | 原版消费点（reference） | 适配决策 |
|---|---|---|
| `Console Password` | `_common/settings.h` 声明；`to_console.c` 的 GUI↔服务 IPC 口令 | **N/A**：鸿蒙单进程无 IPC 通道（C5 决策） |
| `PipeSyslogMsg` | `_services/async_log.c` 的 GUI 管道开关 | **已由机制承担**：`console_pal.c` 事件通道直接投递 Syslog 事件 |
| `HttpBaseDirectory` | 仅 `_common/settings.h:61` 字段声明 + `_services/settings.c:67` 注册表项，**全工程无消费点**（v4.74 无 HTTP 服务） | **N/A**：保留键、不接线、不加界面 |
| `LastWindowPos` | `_gui/gui_settings.c:725/739` 读写窗口位置 | **N/A**：窗口由 ArkUI/系统管理 |
| `Hide` | `_gui/gui_main.c:664` 启动隐藏到托盘 | **N/A**：鸿蒙无托盘；后台运行由长时任务 + 常驻通知承担（C4） |
| `UseEventLog` | `_services/async_log.c:166` `SVC_ERROR` 写 Windows 事件日志 | **N/A**：日志走 `SaveSyslogFile` 落盘 + 事件通道 |
| `Donot verify firewall` | `_main/firewall.c:17/51` 防火墙例外检查 | **N/A**：鸿蒙无 Windows 防火墙概念 |

结论：**待接线键数为 0**。这些键若随迁移的 ini 出现，值不被消费但**保存时原样保留**
（`PalIniSet` 逐行替换登记键、其它行不动），回归见测试方案 §9.5。

## 2. 阶段方案

### 阶段 A：真机基线回归（阻塞项最小、收益最大）

## 3. 测试方案补充

1. **DHCP 测试**：完整二层广播需真机 + 同网段 PC；模拟器上可先做**回环单播**自测（`m2tool dhcp` 令 `flags=0`，服务器按单播回包），已验证 DORA/租约/池耗尽等报文语义，见测试方案 §6.10.1。
   - 工具：`tools/m2tool.c` 的 `dhcp discover|request|release|decline <ip> <port> <mac> [requested-ip]`；PC 侧用 `netsh`/scapy 对拍。
   - 用例：DH-01 DORA、DH-02 租约持久化、DH-03 BootFile+siaddr、DH-04 池耗尽、DH-05 自定义选项 42/120。
2. **组播测试**：`otftp2` 增加 `mcast=<group>:<port>`；两个客户端同组，验证 RFC2090 的 ACK/超时行为。
3. **回归门禁**：已完成 A4——`entry/src/main/cpp/tests/host/` 新增独立 CMake 宿主测试工程（不参与 HAP 构建），
   覆盖 `TranslateParam2Value`/`TranslateExp`（DHCP 自定义选项值）、`AddrInc`/`haddrtoa`、租约池排序/查找/过期判定；
   入口为 `tools\run-host-tests.ps1`，86 条断言通过（含 A1 `Enable IPv4` 配置键回归、A2/A3 未登记键保存后保留），
   见测试方案 §9.5。`DHO_CUSTOM` 报文编码待后续补齐。
4. **自动化冒烟**：已完成 B1/B2——`entry/src/ohosTest/ets/test/Smoke.test.ets` 覆盖配置键落盘、服务启动日志、
   回环 RRQ/WRQ 与纯 IPv6 回环（`::1`），`aa test` 在模拟器上 6 用例全部通过，见测试方案 §9.6；`uitest dumpLayout` 用于 A1 开关实测。
   `m2tool` 作为服务探针。
5. **对拍矩阵**（沿用 §7 通过标准）：P0 全过；P1 ≥95%；差异必须归入 §5 平台偏差或缺陷表。

## 4. 风险与决策点

| 风险 | 影响 | 对策 |
|---|---|---|
| 无真机 / 无二层网络 | A、B7、C1 阻塞 | 先做 B1~B6 的代码与单元测试，真机到位后集中对拍 |
| 鸿蒙组播权限/加入组限制 | C1 可能降级 | 真机先做最小的 `IP_ADD_MEMBERSHIP` 验证，失败则组播列为平台偏差 |
| `bootpd.c` 依赖 Win32 网络接口 API | B1 工作量 | 先在 `ip_pal.c` 做网卡枚举/广播的 PAL 验证，再移植主体 |
| 27 个 DHCP 键使 ini 变大 | 可忽略 | 与原版键名一致优先 |
| GPLv2 合规遗漏 | 交付风险 | D4 前做一次许可证头审计 |

## 5. 建议顺序

1. **A1/A2 + A6**（真机通路与 LP64 审计）——无真机则跳过 A3~A5。
2. **B1→B2→B3**（DHCP 主体与配置），**B4/B6** 随后，**B7** 与 A3 合并执行。
3. **C1/C2**，**C5** 视优先级。
4. **D1~D5** 在全部 P0 用例通过后启动。
